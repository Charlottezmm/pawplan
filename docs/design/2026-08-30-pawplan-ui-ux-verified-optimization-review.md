# PawPlan UI / UX 经验证优化清单

- 日期：2026-08-30（Asia/Shanghai）
- 状态：视觉方向已确认；第一至第三批均已完成实现与本地验证，独立 Import 幂等设计仍未纳入
- 基线：`2180554cc265ad4cd4d5a89857bc7595e16efcde`
- 范围：PawPlan v1 formal controlled beta，Web 与移动端同等重要
- 依据：当前代码、README、已确认的 2026-08-27 产品精简方案，以及 390px 生产页面只读核对

## 1. 结论

PawPlan 当前不需要再做一次全产品重设计。更合理的路线是：

1. 先修复会让界面状态与持久化状态不一致的可靠性缺口；
2. 再改善 Review、Inbox、Today、Login/Join 和 Import 的高频交互；
3. 最后局部收敛动效、反馈组件、文字层级与移动端可访问性；
4. 保留已经验证的真实分钟课表、四项主导航和 Review-first 安全边界。

产品表达采用一个明确原则：

> 面向普通用户时，PawPlan 是温暖、简单的个人计划工具；底层继续保留严格的权限、幂等、冲突检查、审计和 readback。安全机制正常工作时不抢占注意力，出错或需要确认时必须清楚可见。

这不是让安全机制“消失”，而是把 `patch`、`operation index`、token scope 等内部术语放入按需展开的技术详情；用户首先看到的是“发生了什么、当前是什么状态、下一步做什么”。

### 1.1 已确认的布局方向

2026-08-30 的方向草样确认了以下布局骨架。后续视觉改动可以沿用它的版式、密度与气质，但不能照搬其中与当前数据模型冲突的精确时间和导航。

桌面端：

- 左侧是 Today 的日期、负载摘要、待审核入口和任务列表；
- 右侧是只读的真实时间轴，显示课程、会议、健身等确有起止时间的固定安排；
- 用空白和细分隔线形成层级，减少卡片套卡片和装饰性阴影；
- 完成任务先留在原位置显示完成态，不立即飞到列表底部。

移动端：

- 不把完整时间轴压进窄屏；使用日期、任务负载、容量条、待审核入口和任务列表；
- 任务仍显示“上午 / 下午 / 晚上 + 估时”，不能从粗粒度时段推导出 `14:00`、`20:30` 等虚假钟点；
- 底部保持 `今天 / 计划 / 收集 / 审核`，账户能力进入头像菜单或底部面板；
- 条件式主操作只在确有超载、未完成任务或待审核建议时出现，并为底部 safe area 留足空间。

时间与容量语义：

- “剩余任务量”只统计未完成任务的估时；
- “最长固定空档”只根据真实固定时间块计算；
- 容量条必须分别说明固定占用、待办估时和未占用容量；
- 精确时间轴不承载只有 `date + daySegment + estimatedMinutes` 的普通任务；如未来要增加精确任务时间，必须先修改数据和交互契约，不能只改显示。

Review 与重排语义：

- 已有草稿时使用“查看 N 条调整建议”，进入独立 Review 页面；
- PawPlan 未真正触发外部 Agent 时，不能用“交给猫重排”暗示点击后会自动生成或应用计划；
- 无论入口文案如何变化，最终日程写入仍必须经过 Review、Apply 和 readback。

视觉气质：

- 保留暖纸背景、深绿主色、大日期、低阴影和细线分组作为设计方向；
- 草样颜色只用于方向判断，实施前仍要测正文和辅助文字对比度；
- 猫可以承载品牌和提示，但不得用装饰性状态暗示未被持久化验证的 Agent 成功。

## 2. 必须保持的回归边界

后续任何 UI 优化都不得破坏以下规则：

- 移动端主导航保持 `今天 / 计划 / 收集 / 审核` 四项；不恢复第五个“更多”。
- Review 保持独立、始终可访问的主入口；badge 为 0 时不显示焦虑提示。
- Agent 建议继续遵循 `Review -> Apply -> Readback`；Review、草稿、建议都不等于已经生效。
- 不恢复每日自动 Review、自动逾期顺延或后台自动排期。
- 不在课表空白区域自动填任务，也不把任务的上午/下午/晚上推测成精确小时。
- 固定课程继续按真实分钟定位和真实时长显示；44px 命中区通过透明 hit area 提供，不能改变视觉高度。
- 重叠日程只标示冲突，不自动移动；地点缺失显示“地点待确认”，不能猜测。
- Inbox、Backlog、Archive 保持不同语义：
  - Inbox：尚未决定是否进入计划的捕获内容；
  - Backlog：用户明确移出当前排期、但仍保留的任务；
  - Archive：历史记录。
- `/more` 目前作为兼容路径保留，不进入主导航；删除前必须先处理仍返回 `/more` 的 BackLink。

## 3. P0：先修可靠性与数据安全

### 3.1 Today 状态写入失败时回滚

现状：`today-view.tsx` 中完成/卡住切换先更新本地 UI，随后丢弃 `PATCH /api/tasks` 的响应。请求失败时，界面会暂时显示成功，服务端仍保留旧状态。

优化：

- `patchTask` 返回并检查结构化响应；
- 乐观更新前保存该任务的旧状态；
- 网络异常、非 2xx 或响应无法验证时回滚；
- 在任务附近或统一 notice 中说明“更新失败，任务仍保持原状态”；
- 防止同一任务在请求未完成时连续重复切换。

验收：

- 成功路径只更新一次；
- 4xx、5xx、离线和无效 JSON 都能恢复旧状态；
- 刷新页面后状态与成功提示一致；
- `prefers-reduced-motion` 下不执行 FLIP Web Animations 动画。

### 3.2 Login / Join 防锁死与表单语义

现状：网络异常或 `response.json()` 抛错会让按钮停在“处理中”；输入框只有 placeholder，没有完整表单语义；无密码找回能力，却没有充分利用系统密码管理器。

优化：

- 使用 `try / catch / finally`，所有失败路径都恢复按钮；
- 为计划空间名称、密码和邀请码增加真实 `<label>`；
- 增加 `name`、`required`、`autoCapitalize="off"`，并正确设置：
  - 登录密码：`autoComplete="current-password"`；
  - 创建密码：`autoComplete="new-password"`；
- 创建模式增加确认密码和显示/隐藏密码；确认密码只做客户端一致性校验，不改变服务端凭据契约；
- “没有自助找回”只提醒一次，并用清楚中文说明；
- Join 首屏增加两句产品价值和创建后的去向；
- 用户可见文案将 `Workspace 名称` 统一为“计划空间名称”，内部字段与数据库命名不必跟着修改。

验收：

- 空字段不发请求；
- 两次密码不一致时就地提示；
- 离线、服务端错误和非 JSON 响应不会卡住；
- iOS/macOS 密码管理器能够识别登录与创建模式；
- 认证成功后的导航方式以 session 正确性为先，不强制为追求动效改成 `router.push()`。

明确不做：把明文密码复制到剪贴板、临时设计 recovery phrase，或在没有完整安全方案时扩大认证架构。

### 3.3 Import 默认安全、可去重、冲突可见

现状：`plan.md` 和 `timetable.csv` 文本框默认装入可保存的示例；重复保存课表会重复创建记录；warnings 与 conflicts 视觉等级接近。

优化分两步：

第一步，局部安全修复：

- 输入框默认空白；
- 示例放入折叠区或“填入示例”按钮；
- 删除占整张卡片的“HTML 暂未开放”面板；
- 所有用户可见标题、fallback error 和预览标签统一为中文；
- warning 与 conflict 显示数量、语义和下一步。

第二步，数据行为设计：

- 预览行明确标记“新增 / 已存在 / 冲突”；
- 相同导入重复保存不能新增重复记录；
- 存在未处理冲突时不能静默保存；
- 保存结果必须返回实际新增、跳过和冲突数量，并读回代表性记录。

第二步涉及后端判重规则和幂等契约，实施前需要独立技术设计，不能只在前端隐藏重复行。

验收：

- 新打开 Import 页面无法误存示例；
- 同一课表连续保存两次，第二次新增数为 0；
- 冲突不会与 warning 混为同一视觉状态；
- 保存成功后刷新，预览结论与持久化记录一致。

### 3.4 应用级 loading、error 与 not-found

现状：App Router 下没有统一的 `loading.tsx`、`error.tsx` 或 `not-found.tsx`。

优化：

- 先增加一个 `(app)` 级 loading boundary，而不是为每个 route 复制 skeleton；
- 增加 `(app)` 级 error boundary，提供“重试”和“回到今天”；
- 增加全局 not-found 页面；
- 只有在测得某个区域独立变慢时，再为该区域增加 Suspense 和匹配布局的 skeleton。

验收：

- 数据库延迟时旧页面不会表现为无反馈冻结；
- 数据读取失败不会暴露原始 Next.js 错误页；
- loading 结构在 375/390/430px 不产生跳动或横向溢出。

## 4. P1：高频流程可读、可点、可恢复

### 4.1 Review：保留独立页面，降低内部术语密度

Review 是 PawPlan 的核心安全界面，不移出主导航，也不折叠成 Today 的临时弹层。

优化：

- Today 有待确认内容时增加一条独立入口，但入口仍跳转到 `/review`；
- 保留现有 Before / After 结构，改成中文“原计划 / 新计划”，并压缩成一眼可扫的时间或状态差异；
- 分开呈现：
  - 受保护：说明“受保护，不会自动修改”；
  - 已跳过：说明“当前状态已经无需执行”；
  - 冲突：说明“任务已变化，需要重新确认”，并给出明确处理动作；
- 主要提交按钮直接说明为什么不可用，例如“还有 3 项未决定”；
- 正常状态只显示用户需要的原因和影响；patch ID、operation index、agent run 等放入“技术详情”；
- 长错误和 apply readback 使用 notice，不塞进 pill；
- 多 patch 仍按现有 patch 边界应用。先显示逐 patch 进度，不在本轮重构成新的批量 API。

验收：

- 用户不理解 patch/operation 也能完成审核；
- 受保护、跳过、冲突不再合并成一个模糊数字；
- disabled 按钮旁无需猜测剩余动作；
- Apply 后继续执行 stale-state 检查和最终 readback。

### 4.2 Inbox：先选去向，再填写必要字段

优化：

- 展开条目后先选择“任务 / 日常”，只显示对应表单；“今日杂事”继续作为单独快捷动作；
- “今天/明天”快捷按钮直接显示实际默认值，例如“今天 · 上午 · 30 分”；
- 所有移动端输入保持至少 16px 字号，控件命中区至少 44px；移除会覆盖这些规则的 `!text-xs !py-2`；
- 重复规则由“每天”快捷项和星期切换控件表达，不直接要求用户输入 `mon,wed,fri`；
- 校验错误放在字段附近并标记 `aria-invalid`；成功反馈放到统一 notice/toast；
- 修复“刚刚 前捕获”为“刚刚捕获”；
- 删除必须有可恢复机制。若后端没有可验证的恢复能力，则先使用明确确认，不制作虚假的 Undo。

验收：

- 展开一条 Inbox 记录时不会同时看到两张完整表单；
- 快捷提升不会隐式写入未展示的日期、时段或估时；
- iOS 输入不触发页面缩放；
- 删除后刷新页面，反馈与真实状态一致。

### 4.3 Today：把当天负载和待确认事项放到主层级

优化：

- 日期、任务数、剩余时长成为主要信息；问候语降级但保留温暖语气；
- 将“待确认建议”从状态句中拆成独立可点行；
- 有超载或未完成任务时，把“交给我重排”放到警告附近；它仍只进入 Review，不自动创建或应用修改；
- 折叠任务行保留“时段 + 时长”，项目、track、context 等进入详情；
- 完成任务后先在原位置显示完成结果，避免卡片立即飞离点击位置；下一次加载再统一沉底；
- 区分操作层级：延后为主要次级操作，卡住为状态切换，移出排期为安静但明确的危险操作。

验收：

- 375/390/430px 首屏能看到日期、剩余量和第一项任务；
- Review 待确认入口不埋在长句中；
- 完成一项任务不会引起不可预期的大范围重排；
- 不新增自动 Review 或自动排期。

### 4.4 Plan：减少导航拥挤，但不合并业务对象

`任务 / 日程 / 项目 / 稍后处理 / 归档` 是不同视图，不应把 Inbox、Backlog、Archive 强行合并成一个池。

优化：

- 手机端 Plan section 导航使用可横向浏览或等价的紧凑方案，保持 44px 命中区；不再强制塞进固定四列；
- `日 / 周 / 月` 保持为一个三项视图切换；
- “改期”不是时间缩放层级，改名为“手动改期”并从 `日 / 周 / 月` segmented control 中分离，但保留当前直接改日期/时段的功能；
- 任务摘要只保留时段与时长，移除默认“待办”和重复的未分类信息；
- 固定占用在有内容时默认更容易看到：优先尝试默认展开或紧凑摘要，不在本轮把所有页面重做为统一连续时间轴；
- 任何时间轴优化都不得把粗粒度任务伪装成有精确起止时间的日历块。

验收：

- 375/390/430px 不换行挤压、不横向溢出；
- 用户能区分“查看日/周/月”和“直接修改任务日期”；
- 真实分钟课表、重叠显示和固定占用规则全部保持。

### 4.5 移动端账户与弹窗

优化：

- 四项底栏保持不变；右上角账户入口在手机端打开底部面板，提供设置、导入、邀请管理和退出；
- 先修现有延后弹窗：Escape、打开后聚焦、关闭后恢复焦点、焦点约束、滚动锁；
- backdrop 只在 `event.target === event.currentTarget` 的 click 上关闭；
- Plan/Month 详情在移除页面 transform 后，再复用一个经过验证的 dialog/sheet primitive；
- native `window.confirm` 当前功能上是安全的。在共享 dialog primitive 通过键盘、触控和读屏测试前，不为了品牌外观仓促替换。

验收：

- 单手操作不需要点击最难触达的顶部小目标完成主要流程；
- Escape、Tab、Shift+Tab、关闭后焦点恢复均可验证；
- 滚动弹窗内容不会误关闭；
- 底部面板不遮挡 safe area 或四项导航。

## 5. P2：局部收敛视觉与动效

### 5.1 动效

- 删除 `.paw-page` 的 translate 入场和逐项 stagger；如需路由过渡，只保留短 opacity fade；
- Web Animations API 的 FLIP 显式检查 `prefers-reduced-motion`；
- 猫的常驻循环动画最多保留一个，并优先改成状态变化时触发；
- 进度环从 800ms 缩短到约 350ms；
- 只在本次触及的组件中统一 duration/easing，不执行全仓机械替换。

### 5.2 反馈、空态和状态颜色

- 建立一个 Notice/Toast primitive：`info / success / warning / danger`，支持 `aria-live`；
- success 可自动消失，error 保持可见且可关闭；
- pill 只承载短标签，不能装长错误、冲突详情或 readback 段落；
- 新触及的空态统一使用现有 `EmptyState`，但 action 必须与真实页面能力匹配；
- 任务状态主要用结构、文字和 checkbox 表达；系统状态使用反馈色；accent 只用于可交互和待处理提醒。

不要求一次性替换仓库全部历史反馈组件；先覆盖 Today、Review、Inbox、Login 和 Import。

### 5.3 字号、字重与对比度

- 将实际加载范围外的 `650 / 750 / 800` 收敛到已加载字重；
- 先修用于正文、移动底栏、section label 和辅助说明的低对比文字；普通文本对比度目标为至少 4.5:1，不能使用约 3.8:1 的候选值冒充 AA；
- 移动底栏文字从 10px 提高到 11–12px，并保留四项布局；
- 清理本轮触及组件中的 `!text-xs`、原始 Tailwind 颜色和与 token 冲突的 spacing override；
- 不在本轮删除 Tailwind、建立全仓 lint 禁令或机械重写 5,000 多行 CSS。

### 5.4 卡片、纸张与猫

- 仅在 Review、Import、Settings 等“卡片套卡片、pill 装段落”的密集区域减少不必要容器；
- 阴影保留给真正浮起的 sheet、popover 和 toast；普通分组可使用间距和 1px 分隔线；
- 不进行全局圆角、阴影和配色替换；先做真实页面对比稿并验证信息密度；
- 猫保留为品牌与状态辅助，不让装饰性动画暗示 Agent 已成功；只有基于真实持久化状态时，猫才能表达“已生成 / 等待确认 / 已完成”。

### 5.5 字体

当前已经显式加载 `Noto Serif SC` 作为中文 display face，Fraunces 只承担拉丁字符和数字不等于功能缺陷。

本轮只做：

- 测量冷启动字体请求、首次内容绘制和布局偏移；
- 确认 `font-display` 与实际 Google Fonts unicode-range 行为；
- 只有测量证明字体造成明显性能或视觉问题时，再决定自托管、换字体或进一步 subset。

不根据“Fraunces 不含 CJK”这一点直接重做整套字体，也不在没有视觉对比稿时更换全局配色。

## 6. 产品术语清理

这是新增方向建议中收益最高、风险最低的一项。

建议用户可见术语：

| 内部概念 | 用户术语 | 说明 |
| --- | --- | --- |
| workspace | 计划空间 | 登录、创建和账户文案统一 |
| inbox | 收集 | 页面标题也使用“收集”，可在说明中称“暂存区” |
| agent patch / draft | 调整建议 | 正常流程不暴露 patch |
| review | 审核 | 主导航与页面标题统一 |
| backlog | 稍后处理 | 表示明确退出当前排期 |
| archive | 归档 | 只表示历史记录 |
| conflict | 冲突 | 补充发生原因与下一步 |
| protected | 受保护 | 明确说明不会自动修改 |

内部数据库、API、日志和测试可以保留稳定英文名，不为文案一致性制造无关迁移。

## 7. 本轮明确不纳入

以下方向会改变已确认的产品模型，或收益不足以支撑当前复杂度，因此不进入优化清单：

- 移除 Review 主导航，把 Review 只做成 Today banner；
- 用“更多”替换底栏中的“审核”；
- 合并 Inbox、Backlog 和 Archive；
- 把 Today、周、月全部重做成一个连续时间轴；
- 为粗粒度任务增加隐含精确起止时间或拖拽排期；
- 恢复自动逾期顺延、批量“计划破产”或后台自动重排；
- 全仓删除 Tailwind、一次性替换所有 CSS、圆角、阴影、字体和配色；
- 为 Review apply 新建跨 patch 批量 API；
- 在没有后端恢复能力时制作假的删除 Undo；
- 为视觉一致性立即替换原生 confirm，而没有先完成可访问 dialog primitive；
- 删除 `/more` 兼容页，却不处理仍指向它的 BackLink；
- 把已废弃的逾期重规划技术方案重新当作当前产品方向。
